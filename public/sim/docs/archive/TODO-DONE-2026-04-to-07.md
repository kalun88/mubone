- [x] **#155 Pot scaling — response curves + output windows** — Closes the mapping-shape gap deferred in #150. A pot can now be given a response curve and confined to part of its destination's travel, set **in the destination's own units** (`−600 ¢` to `+600 ¢`, `200 Hz` to `8000 Hz`) rather than percentages. New **`js/scale.js`**: `scaleControl()` (exponent γ then remap into `[lo,hi]`, both domain and codomain 0–1 so it composes with any destination) plus `toNorm`/`fromNorm` for unit conversion. Applied in `processChannel` between the deadband check and the `×127` dispatch — **deadband stays on the raw value**, since checking it after shaping would make a narrowed pot's steps fall below the threshold and stop sending entirely. Stored **normalised**, not in destination units, so retargeting a pot keeps the same fraction of travel instead of corrupting the bounds. Written as a standalone helper so MIDI CC mappings can adopt it without a rewrite; deliberately not wired into `midi.js` yet. **The enabling change is that every cc `ACTION` now carries a structured `range: { min, max, unit, int, curve, maxFn }`** and `fmt` is *derived* from it via `fmtRange()` instead of hand-written — 36 actions annotated. That collapses part of the debt of `ACTIONS` and `MAPPABLE_PARAMS` being two parallel range tables. It also immediately caught a hand-written lie: `preset_select`'s **label** claimed "(1–20)" for a 40-entry `PRESETS` list. Ragged cases documented rather than smoothed over: `grain_k`'s ceiling is the particle count so it uses `maxFn`; `recency_cc`'s `0 = all` is a sentinel *above* 16 and stays out of `range`, unreachable from a scaled pot. New harness **`scripts/verify-action-ranges.js`** — runs every real `ccFn` at v = 0, 63.5, 127, diffs `S` to find which key it writes, and checks the half-throw reading. It compares **shape, not absolute values** (normalised by observed endpoints), because a range is declared in the unit you read while the ccFn stores something else — `grain_dur` declares 1–4000 ms and writes 0.001–4.0 s, and any constant factor cancels. Half throw is the whole test: lin and log agree at both endpoints and diverge hardest in the middle, so a swapped `curve` flag is a 15× error at v=63.5 and invisible anywhere else. **34 ok · 0 mismatched · 2 skipped** (both documented). UI: `min` / `max` / `curve` columns in the accessory table, live in destination units, disabled for button and unbound rows, double-click to reset, and a violet pad number flagging any channel that isn't full-travel-linear. Files: `js/scale.js` (new), `scripts/verify-action-ranges.js` (new), `midi.js`, `accessory-registry.js`, `ui-accessory.js`, `index.html`, `style.css`. Shipped in 1.12 alpha. **Release follow-up: `js/scale.js` must be added to `APP_SHELL` in `sw.js`** — it is the one module the checklist command now reports missing.

- [x] **#132 Erase brush (MVP)** — Momentary hold-to-erase at the main cursor. New `js/erase.js`: while held (**hold F** / OSC `/erase/hold 0|1` / new **erase** panel button), a 30ms ticker removes particles inside the cursor's search radius that pass the **same local recency filter the scan uses** (mirrors `_buildCandidatePoolRadius` — recency ranked from in-radius particles only), so erasing the newest buffers under the cursor reveals older ones. Ek's scoping choices: radius+recency selectivity (not exact-K), momentary hold (not mode toggle), instant per tick (not budgeted scrub). **One hold = one eraser pass:** buffers hidden underneath at first sighting are protected for the rest of the stroke (`_strokeFate` map), so the revealed layer stays audible instead of being re-ranked into the top-N and eaten ~30ms later — release and press again to dig deeper.
