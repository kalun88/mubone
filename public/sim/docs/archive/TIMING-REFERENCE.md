## Key Dependency Chains

```
Hardware DAC
  └─→ Audio sample rate (48kHz)
        ├─→ Render quantum duration (2.67ms)
        │     ├─→ Worklet block rate (375/sec)
        │     │     ├─→ Recording capture batch (16×128 = 2048 samples, 42.7ms)
        │     │     ├─→ Quad capture batch (8×128 = 1024 frames, 21.3ms)
        │     │     └─→ Input meter ring buffer (32768 samples, 683ms)
        │     ├─→ Min grain duration floor (5.3ms = 2 quanta)
        │     └─→ Audify output buffer (1024 frames, 21.3ms)
        │           └─→ IPC audio credits (8 × 21.3ms = 170ms pipeline depth)
        ├─→ FFT analyser (256 samples → 5.3ms window, 187.5Hz bins)
        ├─→ Recording limit (600s × 48000 × 4 bytes ≈ 115MB)
        └─→ Hann envelope (128 samples = 2.67ms fade)

Grain scheduler tick (20ms / 50Hz)
  ├─→ Scheduler lookahead (40ms = 2× tick)
  │     └─→ Grains-needed-per-tick budget (LOOKAHEAD / period)
  ├─→ DOM update rate (every 25th tick ≈ 4Hz)
  └─→ Grain period (user, 50 µs floor post-worklet)
        ├─→ Grain onset rate (1/period, up to 20 kHz)
        └─→ Concurrent voices — budgeted by the AudioWorklet grain pool, not the main thread

Paint ticker clock (independent setInterval, 200Hz poll)
  └─→ Particle deposit (50ms / 20Hz default, adjustable 5–500ms)
        ├─→ S.particles growth  ──→ scheduler per-tick cost is O(particles × seeds)
        ├─→ Audio feature snapshot per marker (rms / centroid / zcr)
        └─→ Live-buffer snapshot refresh (50ms throttle ≈ 20/sec)
              └─→ Grain scheduler candidate search (50Hz)

  NOTE: deposit is NOT on the render clock. It was gated to every 3rd render
  frame under the old `PAINT_INTERVAL` scheme; paint-ticker.js replaced that
  with a free-running fixed-interval clock so deposit spacing is independent
  of frame rate and of input source.

Monitor refresh (~60Hz)
  └─→ requestAnimationFrame (~60Hz)
        ├─→ Render gate (30fps time-gate)
        │     ├─→ Seed trails (120 projection budget/frame)
        │     └─→ All particle/seed/cursor drawing
        ├─→ Mouse/touch input coalescing (1 flush per rAF)
        └─→ Secondary rAF loops (meters, IMU setup)

x-imu3 hardware (100Hz as configured; up to 400Hz supported)
  ├─→ [current] direct serial → imu-setup.parseDataLine → S.imuQuat/imuEuler
  │     └─ no throttle: every sample lands in S at the full device rate
  └─→ [legacy]  Max metro poll (20ms / 50Hz) → WebSocket → osc.js → S.imuQuat
        └─ halves the device rate before it reaches S

  Either way, consumers sample S at their own rates:
        ├─→ Camera orientation (consumed at render rate, 30fps)
        ├─→ Cursor position (consumed at scheduler rate, 50Hz)
        ├─→ Sensor mapping (consumed at render rate, 30fps)
        └─→ Gesture module (windows are in FRAMES, tuned for 100Hz — see #47–49)
```
